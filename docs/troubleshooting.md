# 排障决策树

按症状查，不要乱试。每一行都是原视频/博客中出现过或由步骤逻辑直接推出的真实坑点。

| 症状 | 最可能的原因 | 处理 |
|---|---|---|
| WARP 一直卡在「连接中」 | 还在用默认 WireGuard 协议，被运营商屏蔽/干扰 | 回后台把**设备实际命中的**配置文件协议改成 MASQUE 并保存 |
| 改了 MASQUE 还是连不上 | 改错了配置文件——设备命中的不是你改的那份（配置文件按列表顺序优先命中） | 到「设备配置文件」列表确认顺序与命中关系，改对那份，或调整优先级 |
| 电脑连不上、手机正常（或反之） | 出问题的那台还开着别的 VPN/代理在抢路由 | 关掉所有其他 VPN、代理、旧 WireGuard 客户端，再重连 |
| 手机端连不上 | 手机套用了 MASQUE 的配置文件 | 按原作者博客提醒：给手机单独建一份协议为 **WireGuard** 的配置文件 |
| 收不到验证码 | 邮箱填错 / 进了垃圾箱 / 超过 10 分钟失效 | 核对注册邮箱，查垃圾邮件，重新发送；验证码仅 10 分钟有效 |
| 团队名称提交失败 | 团队名全网唯一，已被占用 | 换名或加数字后缀，不影响功能 |
| 卡在付款页面 | 误以为免费版也要绑卡 | 直接点「取消并退出 / 确定并退出」，免费版功能照常（原作者亲测） |
| 连上但速度慢 | 协议没真正保存 / 命中了很远的 colo | 先重开配置文件确认值是 MASQUE 且已保存；看 trace 的 `colo`；重启客户端重连一次 |
| 老账号早已开通 Zero Trust | 无需重注册 | 直接对现有团队命中的配置文件做协议切换 |
| 向导里找不到「添加设备」 | 入口在集成页深处，或界面改版 | 找功能词：集成/设置 → 服务提供商 → 「使用 WARP 注册您的设备」 |

## 验收脚本

在本机运行仓库自带脚本，确认流量是否真的走了 WARP / Zero Trust：

```bash
python3 scripts/verify_warp.py
# 或机器可读输出：
python3 scripts/verify_warp.py --json
```

- 输出 `PASS (warp=on / gateway)` = 已启用，并打印出口 `colo` 与 IP。
- 输出 `warp=off` = 没走 WARP，按上面三项逐一排查（客户端未连接 / MASQUE 没保存到命中的配置文件 / 其他代理抢路由）。
- 无法访问 trace 页时脚本退出码为 2，先解决本机基础网络。

## 回滚

- 临时停用：WARP 客户端点「断开连接」。
- 退出团队：客户端 首选项 → 账户 → 注销 Zero Trust 登录。
- 恢复协议：后台把设备配置文件的隧道协议改回 WireGuard 并保存。
- 彻底删除：在 Zero Trust 后台删除本次新建的设备配置文件/团队设置（注意：删除团队前确认没有其他设备在用）。
